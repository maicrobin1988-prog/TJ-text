# 飞书画板交付

## 画板承担的内容

本技能不附带飞书账号、连接器或 CLI，也不捆绑 `lark-doc`、`lark-whiteboard`。云端交付需要调用者具备目标文档与画板的读取、写入、图像上传能力和相应授权；相关工具说明仅在已安装或可发现时按需读取。未配置飞书时先完成本地可编辑图稿，并如实标明云端未完成。

默认把研究、判断和概念策划放进同一项目画板的不同区域；内容过多时可拆为少量聚焦画板，并保留统一入口。布局围绕本项目论证，不要求固定区块数量。

| 区域 | 必要内容 |
|---|---|
| 项目认知与研究索引 | 项目身份、版本/日期、已知与缺口；相关维度的研究摘要与深入程度 |
| 证据与专题研究 | 任务书、会议、公开资料、现场照片及案例原页，紧邻它支撑的发现与判断 |
| 当前关键判断 | 跨维联系、根因、机会、优先事项与理由；重要但未知的内容单独标注 |
| 策略与解决方向 | 项目主张、概念推导、策略树、人群旅程、空间/流程动作与成立条件 |
| 前端汇报篇章 | 按论证顺序组织章节，每章挂载主结论、证据编号、建议图示与转场关系 |
| 下一步 | 需要核实的材料、访谈/现场任务、待决策事项及其影响 |

用原生逻辑节点、文字、形状和连线组织关键推导，尽量可编辑、可检索；资料原页以真实截图嵌入，不把整板压成一张图片。复杂分析可用相邻图文卡承载，导图叶节点保持简短。证据放在判断旁，不集中堆为难以对应的附录。

可用 R（研究材料）→ J（关键判断）→ S（策略）→ A（动作）→ P（篇章）编号，或沿用项目已有编号。编号用于回溯关系，不要求为此开发额外系统；同一证据多处引用同一编号，保留原件。

## 截图与来源

截图需可读，保留足够上下文及原页码；必要时完整原页与重点局部并列。图旁写清材料名称/作者或机构、链接或原文件、日期、PDF物理页码/网页位置、可见事实、研究归纳及迁移边界。日期未载则如实标注。

区分现场实景、建成照片、方案效果图、参考意向和AI图。公开网页截图支持什么有限主张，应在图旁说明；搜索结果缩略图不能冒充已经读过的原页。只有链接尚未取到截图时记录缺口，不能伪造证据图。

自有案例库与用户提供的原册可按当前任务权限引用；本 skill 不附带客户原页或将其作为所有项目通用素材。需要更多原案时使用已有案例读取能力，外部材料尽量回到原作者。

## 工具与身份

1. 有可用飞书连接器或 CLI 时优先使用。按实际任务读取已安装的 `lark-doc`、`lark-whiteboard` 及其共享规则；依当前环境的帮助检查身份、命令与写入能力，不把某次环境的路径、token、scope 故障固化为通用要求。
2. 默认以用户身份创建用户可持有和管理的成果。写入前确认目标是本次新板还是用户指定的既有项目板，不编辑方法样板。用户身份不可用时不要默默改成交付用户无权编辑的机器人资源。
3. 连接器/CLI 无法完成时，可以在当前请求授权范围内使用已登录飞书网页新建、导入或编辑。权限门禁按实际反馈处理，不预设一律二次确认，不擅自改变分享或所有者。
4. 云端暂不可写时先完成可审阅的本地图稿，报告具体缺口。区分本地已完成、云端已写入和重开已验证；不要把空白容器或仅可下载的文件当作已交付的飞书画板。

## Draw.io 导入路径的兼容检查

Draw.io 是连接器或 CLI 不能完成时可选的导入路径，不是运行本技能的必装软件。使用此路径时，交付图稿保留原生文本/形状/连线，证据图内嵌而非依赖本地绝对路径。PNG 内嵌在既往验证中可用，但仍需核对当前飞书的实际显示。

多页、多图层图稿导入后可能只出现部分内容。需要在同一飞书画板展示多个板块时，可先整理为单页单图层，平移分区、保留间距，维护节点 ID/引用的唯一性和嵌图数据。导入后通过全览和局部放大确认所有区域实际出现，不能只凭导入进度完成判定成功。

## 完成验收

- 从最终交付链接重开，核对项目身份、所有者或用户可编辑状态、标题、版本及保存结果。
- 全览检查全部内容区域，局部放大核对关键论证和每组证据图；确认不存在缺图、严重溢出、重叠或被裁掉的说明。
- 抽查关键判断能回到原文与来源，策略能连接对应问题，汇报章节确有本项目结论或已标注的待补条件。
- 用画板搜索抽查原生文字，或在编辑界面确认关键节点可独立选取，不把全板位图称为原生导图。
- 保留可用源稿与验收截图。最终回复以飞书入口为主，简述核心判断、策略重点、主要缺口和核验状态。
