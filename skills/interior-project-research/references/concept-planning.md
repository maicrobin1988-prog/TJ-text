# 概念策划与汇报

## 从判断走向主张和解法

研究应回答“项目是什么、为什么现在做、当前最应关注什么”。由此提出为谁创造什么价值的项目主张，再推导概念、设计原则与策略。不要先命名概念再倒找证据，也不把品牌产品或地方图案直接放大成空间。

每项重要研究结论补齐：**发现 → 证据 → 对本项目的含义 → 建议回应 → 待验证条件**。策略进一步解释：

| 内容 | 最低颗粒度 |
|---|---|
| 对应问题 | 回应哪条关键判断，为什么现在回应 |
| 服务对象 | 哪类人或项目角色，在什么活动中受益 |
| 改变内容 | 哪些空间关系、资源配置、体验触点或运营流程发生改变 |
| 具体做法 | 在何处、通过什么机制实现；可以有备选方向与取舍理由 |
| 成立条件 | 所需资源、组织配合、技术、成本、现场或标准条件 |
| 验证方式 | 通过什么资料、推演、观察、反馈或后续指标检查 |

假设示例：“提升协同、体现科技感”仍缺做法。可讨论的方向是“在跨团队活动交汇处配置小型讨论空间，以声学和权限边界保护专注工作”。位置、数量、预约方式及配置标准仍需根据团队关系、活动频率、现有需求与预算核实；此示例不是所有办公项目的默认方案。

解决方向可以落实为功能邻接、开放与私密层级、流线分工、关键场景、空间语言、技术成本原则或分期动作。没有图纸时可以先画关系和使用机制，明确其为策略示意；不要伪装为已经校核的平面或施工方案。

## 按论证顺序组织前端篇章

下面是可组合的论证单元。章节不是固定页数，可以合并、增删、重排，但保留“依据—判断—主张—策略—解法”的可追溯关系。各章在具体项目中尽量用有依据的结论句命名，避免全部写成“背景分析、行业趋势”等资料分类标题。

| 篇章 | 要回答的问题 | 应形成的内容 | 适合的证据与图示 | 承接逻辑 |
|---|---|---|---|---|
| 项目任务 | 为什么现在做，希望改变什么？ | 真实任务、阶段与成功条件 | Brief原文、启动节点、各方目标关系 | 为完成任务，需要理解项目所处环境 |
| 关键洞见 | 哪些业主、行业、区位和人群事实会改变判断？ | 对本项目有意义的少量关键洞见 | 原文截图、现场材料、趋势依据与同行对照 | 这些变化与现有条件形成什么差距 |
| 核心矛盾与优先理由 | 当前最需回应什么，为什么优先？ | 主次清楚的矛盾、机会、影响与决策时点 | 期待与现状对照、因果链、证据引用 | 用优先事项界定本次设计的主张 |
| 项目主张与价值目标 | 为谁创造什么体验或价值？ | 一句可解释的命题、目标与作用边界 | 人群价值图、判断与目标对应关系 | 把价值主张转成原则与取舍 |
| 总体概念与设计原则 | 用什么整体思路统领设计？ | 有推导的概念、原则、采用与舍弃的理由 | 概念推导、原型属性到空间的转译图 | 原则通过哪些策略落实 |
| 策略体系 | 通过什么路径回应关键问题？ | 问题—策略—空间/流程动作关系 | 功能结构、邻接、分区、资源配置或接口示意 | 将策略放到真实使用过程中检验 |
| 人群旅程与关键场景 | 不同人怎样进入、活动、停留和离开？ | 分人群旅程、场景机制与解决方向 | 动线、时序、分镜、场景草图或关键关系 | 场景需要一致的体验与表达 |
| 空间语言与体验 | 希望产生何种感受，如何实现？ | 尺度、层次、光、材质、构件及情绪组织规则 | 意向对照、材料逻辑、概念到空间语汇转译 | 表达接受技术、成本和维护条件检验 |
| 落地优先与待决策 | 先做什么，方案成立还缺什么？ | 实施优先、关键条件、备选取舍与下一步 | 技术成本要点、分期关系、核实及决策清单 | 承接平面与方案深化 |

不要只输出章节名称。每章要有本项目的暂定主结论、论证依据、建议图示、与下一章的承接。资料不足时说明该章能完成到哪里及需要补什么，不用通用话术填成“已完成”的项目论证。

## 概念与案例的转译

文化或品牌原型先提取行为、工艺、节律、尺度、光感等属性，再匹配使用场景和空间载体。说明为什么选择它、舍弃什么，以及它如何影响空间，避免仅做形状对应。

参照案例保留：原案要解决的问题、采用的机制、原页证据、适用条件、与本项目差异和未展示的结果。学会比较同一空间的不同使用模式、同一目标的不同解法，不只比较图片风格。原方案未展示某项研究，不等于原团队没有做过。

## 交付前的内容自查

- 重点是否来自本项目，而非模板、热门词或资料数量？
- 关键矛盾是否有优先理由，策略是否能回到矛盾？
- 是否已给出可讨论的解决方向，以及必要的条件、备选与验证？
- 项目主张、概念、原则、策略、场景和表达是否互相对应？
- 汇报是否能逐章论证，而非十维材料罗列？
- 未确认的目标、推断、参数和案例效果是否被明确标注？
