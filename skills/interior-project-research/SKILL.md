# 项目前期研究与概念策划

把零散项目线索推进到可追溯的策略判断与概念策划。默认用中文，研究成果以飞书画板呈现；入口先展示当前关键判断与简要策略，分区展开研究、解法和篇章。原生逻辑节点组织推导，真实资料截图紧邻所支撑的判断。用户只要求某个专题时，按该范围研究，不自动扩成整套方案。

## 启动与对象核对

允许只凭项目名称、任务书片段、聊天记录、链接、图纸或现场照片启动。先利用本轮资料、已授权项目文件及相关既有研究，整理项目身份、当前阶段、已知条件、来源版本与缺口，不要求用户先填满问卷。

核对项目、业主主体与地点，避免同名企业、同名楼宇或项目别称混淆。缺项不妨碍研究时先推进；对象歧义会改变研究方向时，给出候选和依据，只澄清必要身份信息，不把猜测当作已确认对象。重要内部需求缺失时，先做可独立完成的背景研究，再提出具体访谈或现场核实任务。

## 从研究推进到设计判断

1. **先形成项目全景。** 按 [研究维度与证据](references/research-framework.md) 检查十个维度：项目缘起、业主发展、决策与利益关系、行业外部、城市地域、建筑场地、人群活动、竞对标杆、投资运营、实施条件。相关维度均展开，深浅随项目特质与阶段调整；区分低相关和缺资料。不要过早锁定概念，或只查支持既定造型的资料。
2. **跨维识别矛盾与机会。** 将目标与现状、不同主体的诉求、资源与约束放在一起。每项重要发现都说明“对本项目意味着什么”。研究可以提出和修正假设，不能用企业产品形态、地域符号或流行趋势直接代替项目命题。
3. **判断当下的优先事项。** 综合目标影响、决策时点与返工代价、根因关联、可行动性及证据可靠度，说明本项目当前最迫切或最需关注的事项、依据、优先理由和不处理的潜在后果。按实际情况区分本轮回应、并行核实和后续推进；数量不固定，不按十维生成十条策略。高影响但证据不足的事项优先核实，不忽略也不强行定论。
4. **给出策略与初步解法。** 从关键判断推导项目主张、体验或价值目标、概念原则及策略。每项策略交代回应的问题、服务的人、空间或流程改变、具体做法、成立条件和验证方式。前端策划至少给到功能关系、场景机制、空间动作或技术成本方向；不止于“科技感、协同、品质提升”，也不虚构已完成的平面、参数或工程结论。
5. **重组为汇报论证。** 按 [概念策划与汇报](references/concept-planning.md) 搭建前端篇章：项目任务 → 关键洞见 → 核心矛盾 → 项目主张 → 总体概念与原则 → 策略体系 → 人群旅程与场景 → 空间语言与体验 → 落地优先与待决策。按项目合并、增删、调整，不固定页数；给每章明确主结论、依据、图示及承接关系。汇报按论证推进，不照搬十维调研目录。
6. **制作并验收飞书画板。** 按 [画板交付](references/feishu-board-delivery.md) 组织项目认知、研究证据、关键判断、策略解法和汇报篇章，补充待核实与决策事项。保留事实、各方表述、外部观点和研究推断的区别，结论能回到来源。实际打开交付链接检查保存、图文和原生内容；本地完成不能称为飞书交付完成。

## 贯穿全程的取舍

- 外部研究使用可回溯来源，核对时间、地区、对象与适用阶段。官网宣传可证明主体如何表述自己，不能直接证明使用需求或策略效果。
- 用户最新明确指示控制任务；任务书、会议、图纸和现场资料存在冲突时，保留来源与版本，不能仅凭文件日期擅自消除冲突。未知参数、预算和主体关系明确留缺口。
- 业主的业务同行、同类空间项目和设计标杆分别比较，解释可比性与迁移条件。方案图、建成实景和使用后效果证据分开；不把行业平均数直接当作本项目配置标准。
- 设计策略须能说明哪些由空间回应、哪些需要组织或运营配合。私宅、公共文化等项目按其目标组织研究，不套销售或办公模型。
- 先完成已授权且不依赖缺项的工作，只把影响判断或执行的关键问题交给用户。研究输出应包含结论、优先次序与解决方向，不能以资料汇编或一串问题结束。
